Engine path trust — DLL planting next to a valid openvpn.exe
===========================================================
Host: Windows 10/11 x64, OpenVPN 2.6.14 installed in Program Files.
Date: 2026-11-14. The app itself runs unelevated, as in normal use.

Why this matters
  A signature check on openvpn.exe is not enough. OpenVPN loads its
  tap-windows6/Wintun DLL from its own directory, so anyone who can write to
  that directory can drop a DLL beside a genuinely signed openvpn.exe and get
  foreign code loaded under the elevated engine. settings.json also lives in
  the user profile and previously accepted enginePath over IPC, so pointing
  the app at such a copy was a local escalation primitive.

1. Directory write access, measured by the same probe the app uses
   installed: C:\Program Files\OpenVPN\bin\openvpn.exe
   installed dir writable by current user: false
   temp dir writable by current user: true

2. Signature alone does not tell the two copies apart
   A byte-for-byte copy of openvpn.exe was placed in %TEMP%.
   signature installed: status=Valid signer=CN=OpenVPN Inc., O=OpenVPN Inc., L=Pleasanton, S=California, C=US
   signature temp copy: status=Valid signer=CN=OpenVPN Inc., O=OpenVPN Inc., L=Pleasanton, S=California, C=US

3. engineVerdict() decisions on the real files
   verdict installed: {"ok":true,"reason":"trusted"}
   verdict temp copy: {"ok":false,"reason":"writable-dir"} error=ENGINE_DIR_UNSAFE

   A user-writable engine directory is refused even when the executable is
   perfectly signed, because the DLL beside it is not covered by that
   signature.

4. Unsigned custom build
   signature unsigned stub: status=UnknownError
   verdict custom not picked: {"ok":false,"reason":"writable-dir"}
   The stub lived in %TEMP%, so the directory rule fires before the signature
   rule. The session-pick rule itself is covered by unit tests: with a
   non-writable directory, an unsigned engine is refused with
   "pick-required" unless it was chosen in this session and strict mode is
   off; a signed engine from a foreign publisher is refused as "untrusted".

5. Related changes in the same release
   - main.js no longer accepts enginePath through settings:set; the path can
     only change through the native file picker (engine:pick), which runs the
     same verdict before saving.
   - The verdict is re-evaluated on every connect, so editing settings.json
     cannot select a writable-directory engine later.

Limits
   This is a host-side decision test, not a tunnel test. It does not claim
   protection against malware already running as the same user inside a
   non-writable directory, and live UAC tunnel verification remains pending.
