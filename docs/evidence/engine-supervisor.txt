Notes
-----
- The supervisor keeps running after the launcher returns (the elevation
  wrapper no longer uses -Wait), so it can stop the engine for the whole
  session without a second UAC prompt.
- A stop marker, a dead engine, or a heartbeat older than 30 seconds all lead
  to the same teardown: stop the engine, remove the routes added during the
  run, write engine.status.json, delete engine.ready/engine.heartbeat/
  engine.stop/engine.supervisor.json/engine.pid, and remove the admin stage.
- The session-side stop writes engine.stop and waits for the supervisor. The
  test records zero calls to the old user-token taskkill path.
- A config swapped between the write and the elevated copy changes the
  SHA-256, so the script exits 3 and never starts the engine.
- The heartbeat and stop files live in the user-writable run folder by design:
  a same-user process can already close the UI, so this adds no privilege
  boundary. The elevated script itself is never read from a file.
- The packaged 0.2.14 build was smoke-launched in capture mode and rendered the
  home screen: packaged-0214-home.png. This checks that the built app starts;
  it does not connect a tunnel.

Addendum — hardened supervisor, same day
----------------------------------------
After this transcript was captured, the supervisor script was hardened and the
host suite re-ran green (77/77, including this real-PowerShell test):

- Teardown records the engine process start time at launch and only force-stops
  a PID whose start time still matches, so a recycled PID can never be killed.
- engine.status.json now carries engineStopped, routesRemoved and routeErrors.
  engineStopped=false (the admin stop could not confirm the engine died) makes
  the supervisor exit 5 and keep engine.pid / engine.supervisor.json /
  engine.status.json / the stage, and makes the session report
  ENGINE_STOP_FAILED instead of retrying a kill that cannot do better.
- Route deletion refuses to run when the pre-launch snapshot is missing or
  unparseable (returns -1 instead of guessing), and per-route failures are
  counted in routeErrors; the stage folder is kept in those cases.
- The failure branch (stage-error / tampered after the engine had started) now
  runs the same identity-checked stop and route cleanup.
- launchStaged clears a stale engine.stop before launching and writes one when
  SUPERVISOR_START_TIMEOUT fires, so a wedged supervisor exits on its next
  poll instead of waiting out the heartbeat.

Limits
------
- The UAC prompt, the elevated execution context, and a real OpenVPN tunnel
  were not exercised here. The stub engine loops like a live engine but does
  not create a tunnel adapter or routes.
- Actual removal of tunnel routes on stop was not executed on this host; only
  the generated script properties and the teardown sequence were tested.
  (A later live run on a real tunnel did exercise the teardown; see
  live-teardown.txt.)
- The 30-second crash timeout was exercised once with a 3-second test value,
  not over a long session; no stability claim is made.
